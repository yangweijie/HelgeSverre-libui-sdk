## Chart 拖拽交互修复:拖拽平移"没效果"
根因:`ZoomState::pan()` 在**未缩放(全域)**时是刻意 no-op —— `clamp()` 发现视口宽度已 ≥ 全域宽度就把域重置回 full,所以在一张未放大的图上拖拽平移什么都不发生(用户报"没效果")。

修复(`src/Chart/Chart.php` + `src/Chart/ZoomState.php`):
- 新增 `ZoomState::zoomTo($xMin,$xMax,$yMin,$yMax)`(public,提交框选域 + active + clamp)。
- `Chart::beginDrag` 按状态选模式:
  - 非笛卡尔(饼/环)→ 'none'(双击才 explode)。
  - Shift 按住 → 'pinch'(捏合,不变)。
  - **已缩放** → 'pan'(拖拽平移,原行为)。
  - **全域(未缩放)** → 'box'(拖拽画半透明选框,**松开时缩放进框内区域**)。
- `updateDrag` 的 box 分支只记录 `dragBox=[x0,y0,x1,y1]`,`endDrag` 在松开时把选框转成数据域调用 `zoomTo()`(<4px 视为误点,忽略)。
- `draw()` 新增 `drawZoomBox()`:用 `Brush::rgb(0x3b82f6,0.18)` 填充 + `strokeRect(...,StrokeParams::solid(1.5))` 描边,并裁剪到 plot 区域。
- `resetZoom/setData/setType` 顺手清 `$this->dragBox` 避免残留选框。
- 演示 `examples/chart-demo.php` 提示文案改为:"双击/框选=放大 · Shift+拖拽=捏合缩放 · 放大后拖拽=平移 · 键盘 +/-/= 放大、0 复位"。
- 测试新增 `zoomTo commits an explicit box-zoom domain and clamps to full`,现 12 passed。

结论:libui Area 无原生滚轮/触摸,拖拽手势必须自己解释。框选缩放在"全域"状态给了拖拽即时可见反馈,解决了"拖拽平移没效果"的体感问题。

## Chart tooltip 背景/文字垂直居中微调
- 用户截图反馈:tooltip 背景块上下留白不均,文字偏上,未垂直居中。
- 修复(`src/Chart/Chart.php::drawTooltip`):
  - 高度从 `$fs + 12.0` 减到 `$fs + 8.0`。
  - 宽度 padding 从 `+ 18.0` 减到 `+ 16.0`。
  - 文本 y 从 `$ty + 6.0` 改为 `$ty + $h / 2.0 + $fs * 0.3`,补偿 libui 文本基线,使文字垂直居中。
  - 水平 padding 从 `9.0` 改为 `8.0`。
- 二次修正(用户反馈文字反而偏下超出背景):libui 的 `drawString` y 更像是文本顶边而非基线,改回 `y = $ty + ($h - $fs) / 2.0`;同时把块高再收为 `$fs + 6.0`,宽度 padding 收为 `+ 14.0`。
- 三次修正(用户反馈文字上方、左右仍空):进一步收紧 padding(块高 `$fs+4`,宽度 extra `+10`,系数 `0.58`,x `+5`,y `$ty+($h-$fs*0.72)/2`)。仍不满意。
- **终版修正(用户明确:文字偏左未水平居中 + 文字上方空白 > 半行)**:放弃估算,改用 `Libui\Text\TextLayout::extents()` 实测文字宽高 `[$tw,$th]`,`$w = max(60, $tw + 16)`,`$h = $th + 8`;文本用 `drawString(..., $tx, $ty + 4.0, $w, DrawTextAlign::Center)` 实现水平居中 + 上下等 padding。新增 `use Libui\Text\{Attribute,AttributedString,TextLayout}`。
  - 关键认知:libui `drawString` 的 y 是文本**顶边**(top-left),不是基线——增大 y 文字下移、减小 y 上移(由前几版"y 大则文字裁底 / y 小则偏上"反推确认)。
- 验证:`php85 -l` 干净;`pest` 14 passed。
